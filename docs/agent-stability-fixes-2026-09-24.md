# 持续运行问题修复与复测：2026-09-24

本轮针对 [上一轮实测报告](agent-stability-2026-09-24.md) 的五类问题修复。保留原始消息归档、工具调用配对和有限执行预算；没有增加崩溃自动续跑机制。

## 已实现的修复

1. **启动配置。** 增加 `MAS_LLM_TRUST_ENV`，同步、异步及两种流式请求均可独立于进程代理配置直连。库默认仍为 `1`。本地 `.env` 补齐已由服务端元数据确认的 `MAS_CONTEXT_WINDOW=131072`，设置 `MAS_LLM_TRUST_ENV=0`，并为长任务设置 `MAS_DEFAULT_MAX_TURNS=150`；库默认轮数仍为 20。
2. **Gemma 4 / vLLM 流式结束帧。** 新增显式的 `MAS_LLM_STREAM_COMPATIBILITY=vllm_gemma4`。仅处理完整正文等于 `<turn|>`、`finish_reason=stop`、整数 `stop_reason=106`、匹配模型与服务器标识、无工具增量的已复现结束帧。普通正文、非流式结果、推理内容、工具参数、usage 和错误状态均保留。默认 `standard` 不过滤输出；未知模式拒绝启动。
3. **轮数到限提示。** 四种执行入口均保存并返回最终提示，流式会显示提示；终态保持 `max_turns`，已执行工具不会自动重跑。上下文摘要调用不占主任务轮数。
4. **归档缓存。** 完整引用链扫描期间，超过缓存容量的元数据仍正常读取和校验，但不挤掉可复用缓存。普通读取保留 LRU 行为。记录数和元数据预算仍有上限，未关闭文件指纹或原文完整性检查；既有自定义归档存储无需实现新增缓存接口。
5. **技能加载。** 无效 UTF-8、权限异常、目录配置为文件等错误均记录路径与原因，合法兄弟技能继续加载。使用显式文件状态检查，避免 Python 3.14 路径便利方法隐藏权限错误。缺失目录仍保留原有行为。

密钥、模型地址和模型名称未修改；新的 HTTP 环境配置只作用于模型客户端，不修改系统代理变量。`trust_env=0` 也会忽略 HTTPX 的证书环境设置，证书验证本身仍开启。配置定义见 [configuration.md](configuration.md)。

## 兼容方案的依据

真实服务在完整应用提示和工具对话下仍产生尾标记。分别试过显式设置 `skip_special_tokens=true`、`include_stop_str_in_output=false`，以及追加 `stop_token_ids=[106]`，均未消除问题；因此没有把这些请求参数当作修复。[vLLM 请求字段定义](https://docs.vllm.ai/en/latest/api/vllm/entrypoints/openai/chat_completion/protocol/)。

原始 SSE 捕获证明服务器仍发送该标记，而修复后的同步/异步流式结果与 Session 保存结果均为预期回执。兼容模式只支持已验证的帧结构；更换模型、别名或服务端响应结构后需要重新验证。

## 归档性能与原文检查

同一个 Python 3.10 进程、同一批 5000 个历史归档，对比修复前与修复后实现：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 每次重复校验的 JSON 读取量 | 5000 | 904 |
| 重复校验耗时，两次样本 | 321.80 / 322.46 ms | 113.29 / 111.56 ms |
| 缓存记录上限 | 4096 | 4096 |

JSON 读取减少 81.92%，该次样本耗时约改善 2.86 倍。修复后的缓存为 4096 条、892928 字节的计费元数据。另逐项精确恢复了 1000 条压缩原文和 5000 条历史原文。

完整引用链遍历及配额扫描仍是随文件数增长的操作；缓存不等于常数时间校验。扫描保留已有缓存，跨会话切换后可能暂时命中较少，普通读取会继续替换缓存。测试覆盖记录和字节两个容量边界、压缩链重复访问、文件损坏/删除、超预算单条元数据及自定义存储兼容。
