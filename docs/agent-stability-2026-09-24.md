## 已确认的问题和边界

1. **当前启动配置不足。** 原 `.env` 缺少上下文容量；继承的代理配置另会阻止 HTTP 客户端初始化。需要补齐容量并修正实际运行环境的代理配置，不能把本轮测试进程的临时覆盖视为已经修好日常启动。

2. **模型服务在特定工具对话的流式结果中输出结束标记。** 连续任务的全部 150 个流式任务都返回类似 `RECEIPT CASE-0003<turn|>`，150 个非流式任务正常。按完整应用提示和会话顺序复现后，原始 SSE 最后一个块确实包含 `delta.content="<turn|>"`、`finish_reason="stop"`、`stop_reason=106`；客户端原样展示并保存。最小裸对话没有复现，说明与请求场景有关。应处理该模型服务/适配的兼容性，不能在通用层任意删除合法正文来掩盖问题。[原始复现](/tmp/mas-live-stability-20260924/full-protocol-result.json)

3. **默认长任务只允许 20 个 ReAct 轮次，流式到限缺少最终提示。** 非流式有 fallback 文本，流式只有内部 `run_end.status=max_turns`。本轮默认上限实测为空文本结束；140 步成功依赖显式提高上限。[实现位置](/home/coder/project/mas/core/agent_runtime/turn_machine.py:123)

4. **归档积累后校验开销增加，缓存容量边界存在反复加载。** 离线真实文件测试中，4096 个历史附件重复校验约 39.7 ms、不重新加载 JSON；5000 个附件约 253.9 ms，第二次仍加载全部 5000 个 JSON。元数据缓存有 4096 条和 4 MiB 两个上限，实际先达到哪一项取决于附件结构。每轮开始会重验引用链，提交时也会校验；配额扫描同样随文件数增长。这是长期延迟风险，没有发现原文丢失。[规模测试](/tmp/mas-archive-scale-20260924.md)

5. **技能文件容错缺口。** 一个包含无效 UTF-8 字节的 `SKILL.md` 会抛出未捕获的 `UnicodeDecodeError`，使应用构建失败；当前只捕获 `OSError`。合法兄弟技能不能避免此问题。现有配置路径缺失时只会静默加载空技能集，未触发这一故障。[实现位置](/home/coder/project/mas/prompting/skills.py:40)

另有已知设计边界：快照仍是显式保存，没有崩溃后自动续跑和跨进程工具副作用恰好一次保证；成功归档不自动删除，默认 256 MiB 配额耗尽时停止需要压缩的任务；同步阻塞工具和拒绝取消的自定义 provider 无法强制抢占。因此“正常循环持续运行”与“数天无人值守、异常后自动继续”不能混为同一项验收。

## 证据与后续验收

本轮最长连续应用进程实测约 12 分钟，**没有进行数小时、数天墙钟时间的耐久测试，也没有模拟真实断电**。实际压缩压力以当前保守 UTF-8 估算器的预算为准，并未让服务端真实 token 数达到 131072。建议先解决启动、流式兼容和到限提示，再进行小时级持续验收；数天无人值守还需要明确自动保存/恢复、归档容量与故障处理策略。
