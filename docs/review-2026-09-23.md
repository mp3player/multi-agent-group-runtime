# 单 Agent 重构审阅与修正

本文保留静态审阅阶段的记录。后续已完成[测试验收](testing-2026-09-23.md)：Python 3.10.18 和 3.14.0rc2 各 296 项通过，包含针对下列修正的 56 个回归用例。

审阅基线：`636246e3aaddede2c8484fdaad96330e9c260e2c`。范围包括 Group 分离结果、保留的单 Agent 运行链路，以及两者交界处的配置和公共 API。

结论：当前 application → Agent/runtime → model/tools 的依赖方向可以保留；Group 已不参与运行链路。需要修正的主要是失败处理、工作目录和资源生命周期的契约，而不是再增加一层框架。这是基于源码的判断，尚无本轮运行验证。

## 参考依据

- [Pi 的 Agent 循环，固定版本 898ab80](https://github.com/earendil-works/pi/blob/898ab804050730e9dcefb4443875d5a932aa6a32/packages/agent/src/agent-loop.ts)：在执行工具前判断模型停止原因；错误和中止终止当前执行，因长度截断的工具调用不执行。这里借鉴这一约束，采用抛出 `LLMError` 的本地处理方式，不复制其代码或整套调度能力。
- [Pi 的 Agent 状态封装](https://github.com/earendil-works/pi/blob/898ab804050730e9dcefb4443875d5a932aa6a32/packages/agent/src/agent.ts)：运行占用、状态、事件和请求上下文各有明确入口。项目已有单次执行保护与上下文副本，保留这些边界。
- [OpenHands SDK 架构](https://docs.openhands.dev/sdk/arch/overview)：Agent 行为、Conversation 生命周期、工具和 Workspace 分开组织，应用消费 SDK。我们保留应用层资源所有权，并明确工具工作目录，不引入服务器或远程工作区。
- [OpenHands LocalConversation，固定版本 6ebd820](https://github.com/OpenHands/software-agent-sdk/blob/6ebd820d10794f1b52bb06ef6c19512888a1401b/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py)：工作目录来自 Workspace，而不由进程 cwd 隐式决定每次执行的目标。

## 已实现的修正

以下问题多数来自重构后保留的旧实现，不能全部归因于最后一次 Group 文件分离。P1 表示可能错误执行工具；P2 表示常规功能或契约缺陷。修正状态均为“代码已修改、静态审阅”，不代表回归测试通过。

| 优先级 | 问题与触发条件 | 修正及位置 |
| --- | --- | --- |
| P1 | HTTP 200 的 SSE 中包含 `error`、坏 JSON，或未收到结束原因便 EOF；此前可能把部分回复当成功，并执行积累的工具调用。非流式 `length` 等状态也被忽略。 | [SSE 解析](../core/llm_runtime/sse.py)、[HTTP 适配器](../core/llm.py) 拒绝错误事件和未完成的流；[响应解析](../core/agent_runtime/response_parser.py) 在提交消息、执行工具前拒绝截断、过滤、错误和中止结果。 |
| P2 | 只含 `finish_reason` 的 Chunk 被过滤，流消费者看不到结束信号。 | [流响应累积器](../core/agent_runtime/response_parser.py) 保留结束字段，并将结束 Chunk 交给调用者。 |
| P2 | 自定义工具参数名为 `name` 时，与分发函数的 `name` 冲突，在异常捕获之前抛出 TypeError。 | [ToolRegistry.call](../tools/registry.py) 的分发标识改为仅限位置参数，工具自己的 `name` 留在 kwargs。 |
| P2 | 内置工具找不到文件、写入失败、命令超时或非零退出时返回普通字符串，审计仍标成功，还可能触发成功结束工具的规则。 | 新增 [ToolFailure](../tools/results.py) 文本兼容结果类型；[文件工具](../tools/file_ops.py)、[终端工具](../tools/builtin.py) 标记失败；[ToolRuntime](../tools/runtime.py) 统一记录失败状态。 |
| P2 | 配置其他工作区后，相对文件名和终端 cwd 仍指向进程目录，可能访问错误项目或被自己的边界检查拒绝。 | [ToolRuntime](../tools/runtime.py) 固定每个实例的工作目录，显式根目录的第一个为基准；通过 ContextVar 传给工具，不修改全局 cwd。 |
| P2 | `curl https://example.com` 的 URL 斜线被误识别为本地路径。 | [终端路径扫描](../tools/builtin.py) 区分 URI 与文件路径；静态复审同时修正了 `file://` 被误豁免的问题，提取并检查其解码后路径。该检查仍不是 shell 沙箱。 |
| P2 | 从项目目录外创建应用，默认 `prompts` 指向错误位置，可能启动失败或加载无关目录。 | [PromptConfig](../application/agent_config.py) 使用项目本身的默认提示词目录；显式相对路径仍由调用者决定。 |
| P2 | 工具声明 `requires_approval=True`，即使 enforce 开启，缺少分类规则时仍直接执行。 | [权限策略](../tools/permissions.py) 合并工具要求与分类规则；deny 优先，allow 不抵消显式审批要求。 |
| P2 | 资源关闭失败或被取消后，服务在 finally 中仍标 closed，后续关闭请求被忽略。 | [AgentAppService](../application/agent_service.py) 共享并保护关闭任务，仅清理成功后标 closed；失败进入禁止运行、允许重试清理的状态。 |
| P2 | 公共 JsonMessageSerde 序列化工具结果时丢失 tool_call_id，恢复后的工具对不再有效。 | [消息序列化](../models/serde.py) 双向保留关联 ID。CLI 使用的 JsonSessionStore 原本已保留该字段。 |

另清理了运行层注释中遗留的“member”称呼，没有恢复 Group 入口或兼容导出。

## 保留的设计限制

- 同步工具会占用调用线程，异步期限只能在工具执行前后检查。终端还有自身 timeout，但任意自定义同步工具没有强制取消能力。需要后台长任务时，再设计可取消执行接口。
- `ModelClient` 的四个调用方法以及非流式响应形状仍与当前兼容接口相关。它可以支持当前单 Agent 应用，但还不是通用多供应商消息协议。
- 上下文裁剪按消息条数，流式 usage 尚未统计。流式达到最大轮数仍通过 `run_end.status=max_turns` 报告，没有合成文本回复；这是已记录的现有行为。
- Session、registry 等底层对象仍可直接修改；运行期间仅支持受保护的公共替换入口。今后外部扩展增多时，应进一步收紧可变对象的暴露。
- 关闭任务需要其所属事件循环继续运行。失败清理能否在第二次调用恢复，还取决于模型客户端自身是否支持重试；本层不会宣称资源已经释放。
- Group 归档在主仓库之外，版本管理和搬迁时需单独保留，位置见[归档说明](archive.md)。

这些限制需要在后续实际验收中评估，本轮没有通过增加插件层、调度器或新的持久化系统来扩大范围。

## 验证范围

遵照“先不做测试”的要求，没有新增或执行测试，没有 pytest 收集、应用导入、CLI 冒烟或真实模型请求。现有测试仅作为源码阅读。

采用源码调用链分析、独立静态复审、Python 3.10 语法解析、项目内导入及文档链接检查、diff 空白检查，以及主工作区与隔离工作区的文件完整性核对。

静态复审发现的 `file://` 回归已补正并再次审阅，当前审阅范围内没有其他已识别的阻断问题。语法检查覆盖 70 个 Python 文件，检查了 234 处项目内绝对导入和 30 个本地文档链接；这些数量不代表运行覆盖率。

恢复测试后优先覆盖上表的具体触发条件，尤其是错误/截断流不能产生工具副作用、两个工作区实例的相对路径隔离、关闭请求取消后再次等待、失败工具的审计及终止标记。这些场景本轮均未执行。
