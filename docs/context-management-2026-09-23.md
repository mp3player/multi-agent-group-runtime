# 单 Agent 长上下文实现与验证

本次实现采用已确认的“完整请求预算、增量摘要、近期原文、原文归档”策略。所有运行入口使用同一状态机，不再用消息条数裁剪 active，也不提供摘要失败后丢弃消息的降级路径。

## 实现边界

| 模块 | 结果 |
| --- | --- |
| `context_management/budget.py` | 计入序列化消息、工具定义、参数、输出预留及安全余量；容量未知时阻止推理 |
| `context_management/policy.py` | 保留 system、最新用户原文及必要完整工具批次；按完整单元打包摘要来源 |
| `context_management/manager.py` | 软阈值触发、至多四次摘要请求、候选校验、归档与事务发布；超限仅重试失败的推理一次 |
| `turn_machine.py` / `react_loop.py` | 同步、异步、流式、非流式共用策略；异步归档 I/O 在线程执行，最终发布留在运行所有者内 |
| `session.py` / `context_archive.py` | 稳定消息身份、不可变原文附件、带来源的工作视图、可取消的准备/发布分离、有限元数据缓存 |
| `session_store.py` / `session_codec.py` | 严格 v2 快照和保守 v1 导入；缺失归档允许查看快照，但阻止恢复推理 |
| 应用 / CLI | 配置注入、保留归档工具、`/context`、`/compact [重点]`、压缩事件和用量观测 |

短请求不增加摘要模型调用。默认在估计输入超过可用预算的 80% 时尝试压缩，通常以 55% 为保留目标；硬预算始终执行。服务端明确报超限时扩大安全余量并收紧保留目标，避免估计偏低而原样重试。

摘要只承接历史信息，不成为 system 指令。大工具结果使用带来源引用的预览，其会话可见原文先归档。大来源以完整批次打包；只有单个超大单元才拆成重复携带来源身份和字符偏移的引用片段。四次调用仍无法完成、摘要为空或截断、归档失败、取消、超时或版本变化，均不发布部分摘要。

## 验证

测试使用本地假模型和 `httpx.MockTransport`，没有调用付费服务端。

```bash
env PYTHONPATH=. PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  .venv/bin/python -m pytest -p pytest_asyncio.plugin tests -q
```

显式选择 pytest 插件，避免主机上无关的 ROS 插件进入项目测试过程。

初版全量结果：Python 3.10.18 **670 通过、1 跳过**；用户现有的 Python 3.14.0rc2 **671 通过**。3.10 跳过的一项依赖 `asyncio.Task.cancelling()`，属于版本专属检查。

主要验收场景：

- 单个用户任务在四种入口中连续多次压缩，原始约束与归档可查，工具调用/结果始终配对，工具不重跑。
- 1000 次混合运行，交替使用四种入口，每 11 次在已完成写入后注入服务端故障：1000 次工具副作用各发生一次，910 次完成、90 次明确失败，后续任务正常继续。
- 摘要、主推理和工具 schema 的实际发送内容均经过预算检查；未知容量和超大最新用户输入在模型调用前拒绝，原文仍保留。
- 摘要失败、空白、工具调用、截断、超长、调用额度耗尽、配额/磁盘失败均保留原工作集；流式已输出可见内容后不静默重试。
- 在归档写入、提交准备、历史维护三个阶段取消，然后先完成新运行，再放行旧工作线程：旧操作不能改变新会话状态。
- v1/v2 导入、重复身份、循环引用、缺失祖先附件、损坏附件及快照恢复通过检查。
- 完整、部分、缺失和异常 usage 在四种入口得到验证；缺失值保持未知，账单不伪造零值，完整账单只记录一次。

独立审阅发现并修复了三个重要问题：异步磁盘 I/O 阻塞取消、摘要任意字符切分丢失片段来源、部分 usage 被补成零。修复后分别复审运行时/存储及应用/服务端接入，没有遗留阻塞问题。

## 性能与可用性

同一离线 100 次存储压缩剖析中，重复完整 JSON 加载从 38250 次降到 200 次，计时从 4.45 秒降到 1.13 秒；重复历史缓存附件被消除。优化后的千轮混合测试单独运行约 13 秒。这些是本机确定性测试结果，不代表真实模型延迟、质量或成本。

归档缓存只保存身份、引用和正文摘要指纹，最多 4096 个附件、4 MiB 编码元数据，Python 对象本身另有有限开销。每次仍检查祖先文件指纹，以发现删除和损坏；长链检查及配额统计仍随归档数量增长。归档配额耗尽时明确失败，不自动删除已成功保存的附件。

## 使用与限制

在配置中将 `MAS_CONTEXT_WINDOW` 设置为所选模型的实际容量；需要时设置 `MAS_CONTEXT_INPUT_LIMIT`。实现没有猜测模型窗口，也没有修改现有 `.env`。默认归档目录为 `~/.local/state/mas/context`，默认总配额 256 MiB，可用 `MAS_CONTEXT_ARCHIVE_DIR` 和 `MAS_CONTEXT_ARCHIVE_QUOTA_BYTES` 调整。

`/context` 查看预算与摘要状态，`/compact` 手动整理当前上下文。摘要或预览中的原文可通过保留的 `read_context_archive` 工具分页读取，单页最多 12000 字符；禁用工作区工具时它仍可用。

默认计数是保守 UTF-8 估算，不是模型精确 tokenizer。真实模型的摘要质量、约束保真和费用收益仍需后续带真实任务评测；当前实现不宣称语义无损。归档保存的是进入 Session 的内容，已有终端/工具输出上限之前被截断的内容不在此保证内。

当前归档后端需要 POSIX 的 `flock`、`O_NOFOLLOW`、`O_DIRECTORY`。磁盘工作线程取消后可能留下未引用附件，但没有发布 Session 状态的权限。同步自定义模型/工具仍属于协作式超时。快照保存仍是显式操作，本次没有实现崩溃后的自动续跑。

## 2026-09-24 审阅修复

- 保留历史的预算规划计入 `ContextTransform` 注入的规则，与最终发送请求使用相同的转换过程。
- 工具预览按完整请求的剩余空间分配，25% 为初始偏好；摘要返回及真实归档 ID 生成后，若实际开销超出预算，会结合所有保留消息再次缩短预览，不增加摘要调用或归档写入。工具原文仍存于归档，调用和结果保持配对；连最小预览也放不下时明确失败，保留原工作集。
- 归档发布同时同步会话目录与归档根目录；初始化同步新建路径及规范化的父目录链。初始化失败不删除目录，避免破坏并发创建成功的实例；重试仍重新执行同步。
- 用量统计每个文件只读取一次状态，忽略并发写入正常删除的临时文件，其他读取错误仍会报告。

归档路径的规范化父目录必须可读取并支持目录 `fsync`，否则初始化失败；只有遍历权限的自定义路径不受支持。并发扫描得到的是用量估计。持久性测试验证同步顺序、故障传播、重试及并发时序，没有模拟真实断电或认证所有文件系统的崩溃恢复行为。

修复后全量测试：Python 3.10.18 **699 通过、1 跳过**，Python 3.14.0rc2 **700 通过**；执行与存储专项 **106 通过**。新增回归覆盖四种运行入口、规则注入、大工具批次、中文和 JSON 转义、真实归档 ID 的自定义计数、目录同步失败与重试，以及初始化/用量扫描的并发时序。独立复审未遗留已确认的 P1/P2 问题。
