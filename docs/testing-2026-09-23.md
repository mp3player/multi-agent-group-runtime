## 本轮发现

首轮为 239 项通过、1 项失败。失败的旧断言要求错误文本逐字等于 `响应缺少 choices: {}`；当前实现仍正确抛出 `LLMError`，但已改为更明确的提示。断言现在检查错误类型及 `choices` 诊断信息，不依赖完整措辞。

机器的全局 `PYTHONPATH` 还引入了 ROS 的 pytest 插件，导致最初在测试收集前因缺少 `yaml` 退出。测试命令清空外部 Python 路径，禁用无关插件自动加载，并显式启用项目需要的 pytest-asyncio。没有为这个环境问题添加项目依赖。

## 复现命令

在项目根目录、安装好项目及开发依赖后运行：

```sh
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY \
    -u http_proxy -u https_proxy -u all_proxy \
    PYTHONPATH= PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
    PYTHON_DOTENV_DISABLED=1 \
    BaseURL=http://127.0.0.1:1/v1 BaseKey=agent-test-only BaseModel=fixture \
    .venv/bin/python -m pytest -p pytest_asyncio.plugin -q
```

测试进程的配置隔离不会改写用户 `.env`。测试报告原始输出保留在本机 `/tmp/mas-test-final310.xml`、`/tmp/mas-test-final-root314.xml` 和 `/tmp/mas-before-review-fixes.xml`；这些临时文件不随仓库分发。
